# AI 使用日志（流水层）

> 每次用 AI 写完一个功能当天补记，不要事后回忆。
> 最终从这份流水里挑 8–15 条整理进 `appendix.md`，随项目文档提交。

记录格式固定为七项：日期 / 工具 / 任务 / Prompt / 生成结果 / 人工修改 / 验证。
**最容易漏也最值钱的是「人工修改」和「验证」两栏**，评审看的就是这两栏。

## L-001 · 方案取舍：形态与命名

- 日期：2026-11-01
- 工具：ChatGPT（对话式方案讨论）
- 任务：判断做复刻站、浏览器扩展还是 Web 应用，并确定项目命名
- Prompt（摘要）：给出赛题原文与评分表，要求比较三种形态在创新性、完成度、演示难度上的差异
- 生成结果：建议移动优先 PWA + 可解耦的智能体内核，弃用带 `hduhelp` 前缀的命名
- 人工修改：
  - 不接受"复刻后加功能"的建议方向，改为"意图路由层"定位
  - 补充自己判断：微信小程序需要主体资质与审核，时间不允许
  - 命名改为 `CampusGuide`，中文名暂缓
- 验证：对照通知原文逐条确认没有"必须接入 AI"的硬性要求，也没有"禁止 AI 生成代码"的条款
- 结论：方案定稿，写入 `IDEA.md`

## L-002 · 知识库结构设计

- 日期：2026-11-10
- 工具：ChatGPT
- 任务：设计办事条目的数据 schema，要能支撑"换学校只换 JSON"
- Prompt（摘要）：要求给出字段清单，说明每个字段在检索、渲染、合规举证三个环节的作用
- 生成结果：school / id / category / triggers / title / summary / entry / steps / materials / sla / source / verified
- 人工修改：
  - 增加 `verified` 字段，未核对的条目在界面上显式标注"待核验"，对应诚信项
  - `source` 拆成 title / url / note，允许没有公开直达链接时如实留空，避免编造 URL
  - 增加 `triggers`，因为本地降级检索完全依赖口语化触发词
- 验证：用 7 条真实说法（含 2 条库外问题）跑检索，5 条命中正确，2 条正确走兜底
- 结论：schema 定稿，见 `docs/KNOWLEDGE-SCHEMA.md`

## L-003 · 本地检索（离线降级）算法

- 日期：2026-11-10
- 工具：ChatGPT
- 任务：实现不依赖模型的意图匹配，作为断网和未配置密钥时的兜底
- Prompt（摘要）：给出中文短句匹配的评分方案，要求能解释命中理由
- 生成结果：触发词包含匹配 + 汉字二元组重叠计分
- 人工修改：
  - 把触发词命中权重提到 `6 + 词长`，长词更具体应当更高分
  - 增加 `score >= 4` 阈值，否则"我想申请奖学金"会误命中电费条目
  - 返回 `hitTrigger`，界面显示"你提到了『没水』"，让推荐可解释
- 验证：7 条用例全部符合预期，见上条
- 结论：可用

## L-004 · 后端接口与大模型接入

- 日期：2026-11-10
- 工具：ChatGPT
- 任务：写一个只做"保管 Key + 转发"的服务端接口，前端不得接触密钥
- Prompt（摘要）：Vercel Function + 开发环境中间件共用同一份逻辑
- 生成结果：分别输出 `api/ask.ts` 与 vite 开发中间件两套实现
- 人工修改：
  - 两套实现重复，改为抽出 `server/ask.ts`，开发环境用 `ssrLoadModule` 复用
  - 增加"模型返回 id 必须存在于知识库"的白名单过滤，防止编造条目
  - 增加 15 秒超时与 JSON 解析失败兜底，失败即降级本地检索
  - 未配置 Key 时不报错，直接走本地，保证任何人都能跑起来
- 验证：未配置 Key 的情况下 7 条用例全部正常返回；`tsc --noEmit` 与 `vite build` 通过
- 结论：可用

## L-005 · 移动端界面与 PWA

- 日期：2026-11-10
- 工具：ChatGPT
- 任务：实现行动卡、待办列表，并让网页可以添加到主屏幕
- Prompt（摘要）：React + Tailwind 实现移动优先的行动卡，含步骤、材料、依据、复制
- 生成结果：完整组件代码与 manifest、service worker
- 人工修改：

- 验证：浏览器实测点击示例 → 出卡 → 加入待办 → 待办页显示，链路通
- 结论：可用，待真机复核

## L-009 · 入口打开方式建模（access 字段）

- 日期：2026-11-10
- 工具：ChatGPT
- 任务：实测校务服务网 114 个入口，把"能不能打开"变成可展示的信息
- Prompt（摘要）：如何把"需在钉钉内打开"这类事实结构化，并在卡片上不失礼地表达
- 生成结果：建议用枚举 access 字段（none/login/dingtalk/wechat/alipay/mobile）

## L-010 · 书名深链（urlTemplate）

- 日期：2026-11-10
- 工具：ChatGPT
- 任务：用户说"我想借《平凡的世界》"时，直接给出已填好书名的检索结果
- Prompt（摘要）：如何从自然语言里稳定抽出书名，并拼进检索 URL
- 生成结果：正则抽取《》/引号/「想借X」三种写法，替换 urlTemplate 的 {q}
- 人工修改：
  - 增加疑问尾巴清洗（这本/吗/能借几本），否则会把整句带进检索词
  - 只在条目提供 urlTemplate 时才生效，避免对所有条目乱拼参数
  - 抽不到书名时回退到通用检索页，不生成空参数链接
- 验证：`我想借《平凡的世界》` 生成的链接实测可返回 22 条馆藏结果
- 结论：可用；这是与杭电助手 AI（答"参考链接：暂无"）最直接的差异点
